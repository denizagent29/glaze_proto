# irealglaze — гибрид «нативный менюбар + веб» на Go+Glaze

Дымовой a11y-скелет перед переносом irealstudio на Go+Glaze. Проверяет главный
риск на **Windows**: встаёт ли классический нативный Win32-менюбар **поверх**
веб-контента, работает ли Alt-навигация, читает ли его NVDA, читается ли DOM
чарта и доезжают ли события из меню до страницы.

Стек: [crgimenes/glaze](https://github.com/crgimenes/glaze) v0.0.54 (purego,
без CGo) — нативное окно + WebView самой ОС (WebView2 на Windows, WKWebView
на macOS); `glaze/menu` — нативный менюбар; `glaze.Events` — мост Go↔JS.

## Запуск на Windows

```bat
go run .
:: или собрать:
go build -o irealproto.exe .
```

Требования: Go ≥1.21 и WebView2 Runtime (на Windows 10/11 уже есть).
Готовый `irealproto.exe` (кросс-сборка) лежит рядом.

## Что проверять у себя (с NVDA)

1. Окно открылось, внутри — страница с чартом Rhythm Changes (DOM-текст).
2. **Меню сверху — нативное.** Жми `Alt` — открывается менюбар, пункты
   Файл / Правка / Вид / Демо / Справка. NVDA читает пункты и подменю.
3. Пункт «Файл → Открыть…» вызывает **нативный диалог** Windows.
4. «Вид → Озвучить чарт» (`Ctrl+T`) — страница читает чарт вслух через
   `speechSynthesis` (проверка: меню дёрнуло JS, JS заговорил).
5. «Вид → Фокус в чарт» (`Ctrl+L`) — вызывает `WebView.Focus()`, курсор
   скринридера уходит в страницу (это как раз фикс твоего issue
   [crgimenes/glaze#23](https://github.com/crgimenes/glaze/issues/23)).
6. «Демо → w.Eval в страницу» — Go напрямую вызвал JS.
7. Кнопки в странице «Позвать Go» / «Открыть файл» — обратное направление
   моста: JS → Go-обработчик → ответ в `aria-live`-строку статуса.
8. Статусная строка под кнопками — `role="status" aria-live="polite"`:
   любые сообщения из меню NVDA объявляет сама, без фокуса.

## Платформы (честно, из доков glaze)

- **Windows** — менюбар Win32 цепляется к HWND окна: строка меню сверху,
  ниже WebView2. Это целевая конфигурация.
- **macOS** — `glaze/menu` ставит системный NSMenu (меню наверху экрана,
  не в окне). Правка на маке собрана через нативные селекторы (`undo:`,
  `copy:`…), чтобы Cmd+C/V/X доходили до WKWebView.
- **Linux** — `menu.Set` возвращает `ErrUnsupported` (в коде это не fatal,
  окно откроется без меню). Если Linux нужен — вопрос к проекту glaze.

## Архитектурные заметки

- `glaze.Events`: `NewEvents(w)` до `Run`; в странице появляется
  `window.glaze.events.on/emit`. Go→JS и JS→Go — один мост, без эха.
  JS-обработчики бегут на binding-горутине: окно/диалоги — только через
  `w.Dispatch`.
- `menu.Set` вызывается **до** `w.Run()`, `Options{Dispatch: nil}` (иначе
  повиснет — диспетчер ещё не крутится). `OnClick` выполняется на UI-потоке.
- `w.Focus()` — фокус в веб-контент; `w.Raise()` — окно поверх всех.
- Дальше для настоящего irealstudio: `glaze.AppWindow` с `http.ServeMux` +
  встроенные ассеты (`go:embed`) вместо одной `SetHtml`-строки, и экспорт
  irealb-модулем (порты из `workspace/irealstudio`).

## Структура

- `main.go` — всё приложение (меню, мост, страница).
- `go.mod` / `go.sum` — module `irealglaze`, glaze v0.0.54.

## Режимы запуска

- По умолчанию — **нативный менюбар** (glaze/menu) поверх WebView2. Это целевая
  конфигурация для проверки «гибрида».
- `-webmenu` — **веб-меню**: нативное меню НЕ ставится, меню живёт внутри
  страницы как ARIA-menubar (`role="menubar"`/`menuitem`/`menu`).

```bat
go run .            :: нативное меню
go run . -webmenu   :: веб-меню (ARIA)
```

## Вывод теста NVDA (важно для irealstudio)

Связка «нативный Win32-менюбар + WebView2» **фризит NVDA на ~10 секунд** при
любом переходе фокуса ИЗ веб-документа В нативное меню (Alt). Пустой
`about:blank` с фокусом в документе фризит так же, как полный чарт — содержимое
страницы ни при чём. В логе NVDA это выглядит как повторяющийся
`Starting freeze recovery after 10.0 seconds` (вотчдог размораживает поток).

Причина: NVDA читает WebView2 через отдельное дерево Chromium (IAccessible2),
нативное меню — через Win32/UIA; на границе Chromium не отвечает на запрос NVDA
~10 сек (таймаут). Известная болевая зона: MicrosoftEdge/WebView2Feedback #2330,
nvaccess/nvda#8553.

Следствие для архитектуры: **нативное меню + WebView2 несовместимо с NVDA.**
Рабочий путь — меню ВНУТРИ страницы (ARIA-menubar): фокус не покидает WebView2,
деревья не переключаются, фриза нет. Проверяется в `-webmenu`.

## Rust + egui (egui_proto/) — проигран на a11y меню

Прототип на **Rust + egui**, доступность через accesskit → UIA. Фризов NVDA
нет (без WebView2 и переключения деревьев), но **менюбар ненастоящий**: NVDA
читает верхние пункты как кнопки, `Alt` не открывает, стрелки не ходят.
accesskit/UIA не моделирует menubar как нативное меню. Для irealstudio меню —
критичный слой (незрячий пользователь живёт на Alt+стрелки), поэтому egui-путь
закрыт. Оставлен в репо как референс «быстрый egui без меню».

## Rust + wxDragon (wxd_proto/) — третий кандидат (активный)

Прототип на **Rust + wxDragon** (wxWidgets 3.3.3, статически → один exe).
Настоящее Win32-меню (HMENU) + нативные контролы, без WebView2 — то есть без
фриза NVDA на смене деревьев, который убил glaze-гибрид. Сборка и чек-лист
теста NVDA — в `wxd_proto/README.md`. Это текущий архитектурный кандидат для
irealstudio.
